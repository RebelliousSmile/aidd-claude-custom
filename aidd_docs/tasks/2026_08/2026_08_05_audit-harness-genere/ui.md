## Top actions

1. **Corriger le bezel** (ligne 🔴). C'est le seul défaut du lot qui produit un verdict faux : l'oracle rend un écart contre une implémentation conforme, sur des propriétés mesurées (`padding*`, `gap*`) dès qu'elles sont en %. Le correctif est mesuré et tient en deux propriétés. Handoff : `impeccable` ou une phase de plan dédiée — avec, dans le même lot, l'assertion selftest qui compare la largeur de **contenu** du cadre aux 834 / 390 déclarés (cf. `tests.md` 🔴 et `code-quality.md` 🟡).
2. **Rendre le chrome atteignable et focusable** (lignes 🟡 barre + 🟡 focus). Les deux se corrigent dans le même bloc CSS et se prouvent par la même mesure (`scrollWidth` de la barre, `getBoundingClientRect().right` du dernier bouton à 390 px).
3. **Trancher la langue** (ligne 🟡 i18n). Décision produit avant code : le harness est-il un livrable FR ou bilingue ? Le reste en découle mécaniquement.
