# Audit — plugin `design` (v2.0 → 2.5.0)

- **Date** : 2026-07-25
- **Périmètre** : plugin `design` (skills Markdown + outillage Python/Node), question « qu'apporte la v2, quels trous restent »
- **Mode** : full run, piliers applicables. Read-only.
- **Note globale** : **14 / 20** (justification en fin de rapport)

## Verdict d'une ligne

Architecture exceptionnelle et documentation rare, mais **les garanties du plugin ne sont vérifiées par aucun test versionné**, et deux outils enfreignent l'espace de codes de sortie que l'architecture définit elle-même.

## Ce que la v2 apporte réellement (vs 1.x)

- **Une donnée, un artefact.** Split en quatre artefacts racinés par `release.json` (tokens=valeurs, components=anatomie, policies=mode/usage/adapters, oracle=indices de mesure) : frontières nettes, aucun champ défini deux fois. La 1.x confondait tout dans un manifeste monolithique.
- **Une source unique et exécutable de maturité.** `status.py:33,37` détient `LADDER`/`THRESHOLD` et rien d'autre ne les restate ; `run-gates.py:47` les importe, `02-freeze.md:166` recopie la sortie verbatim et **interdit** d'écrire le statut à la main. La maturité devient calculée, plus asserée.
- **Un registre d'enforcement clos et routé.** La table `REALIZER` de `run-gates.py` (markup→lint-core, le reste→pivots `sc-*`, `unrealized`→None) transforme une règle non typée en **arrêt dur** (exit 2) au lieu d'un contrôle silencieusement ignoré ; une règle non réalisée est **nommée**, pas confondue avec « vérifiée ».
- **Un espace d'exit codes discipliné.** 5 outils sur 7 réservent délibérément 1 aux violations, routent les erreurs d'environnement vers 2 (3 pour 1.x, 4 sous seuil). « Un artefact structurellement invalide est une erreur d'environnement, jamais un drift » est un vrai gain de conception.
- **La maturité s'oppose à la conformité.** `run-gates.py:242-249` : exit 4 prime sur un 0 propre comme sur un 1 violant sous seuil — on ne peut plus revendiquer la conformité sur un contrat immature, tout en continuant à rapporter les violations.
- **Une porte d'entrée read-only (verbe 0 `detail`).** `skills/detail/` sépare EXPLAIN de ROUTE et mappe six classes de cas exhaustives vers les pivots `sc-*` sans jamais invoquer un verbe — la façade cohérente qui manquait à la 1.x.

## Trous restants (architecture)

- **La discipline exit-code n'est pas uniforme** : le trio `adapters/measure/` est l'exception à un contrat sinon propre. Tant qu'il n'adopte pas `sys.exit(main())` + retour 2, la garantie est *énoncée* mais pas *tenue en code* (5 outils sur 7).
- **L'agnosticisme est asseré mais a une exception live connue** (section Tailwind/Nuxt), shippée en violation documentée plutôt qu'en état propre.
- **`checks` enregistré = frontière de confiance, pas de calcul.** Le gate lit les `checks.states.allPass` que `freeze` a écrits ; rien ne re-valide au gate-time qu'ils correspondent à un `--states` frais. Un bloc `checks` périmé ou édité à la main passerait l'échelle.
- **Réalisation pivot = confiance-sur-rapport.** `run-gates.py` relance la `command` d'un pivot mais ne peut vérifier que le rapport correspond au contrat courant ; un pivot qui écrit un rapport périmé-mais-bien-formé est compté REALIZED. Le marqueur `unrealized` couvre le silence, pas la péremption.

## Justification de la note — 14 / 20

Pondération adaptée à un plugin dont la promesse **est** la garantie :

| Dimension | Poids | Note | Contribution |
|-----------|-------|------|--------------|
| Conception / architecture | 40 % | 8.5/10 | Split cohérent, source unique de maturité, registre clos, façade read-only, auto-conscience des dettes. Aucun finding critical/high. |
| Qualité d'implémentation | 30 % | 7/10 | Cœur solide (`contrast.py`, `generate.py`) ; trio `measure/` prototype ; bug latent `$type` ; exit-code tenu par 5/7 outils. |
| Vérification / tests | 20 % | 3/10 | Fixtures riches mais **aucun harnais versionné** ; CI git-ignorée ; cœur d'enforcement non-assuré ; une régression silencieuse déjà passée. |
| Documentation / cohérence | 10 % | 9/10 | ADR, master plan, references, CHANGELOG, mémoire : documentation rare. |

**Composite ≈ 7.0/10 → 14/20.** Le plafond n'est pas la conception (excellente) mais l'écart entre le discours (« fige », « garantit », « enforce ») et la preuve : pour un plugin d'enforcement, **zéro test de régression versionné sur le cœur** est le défaut structurant, aggravé par le fait qu'une régression a déjà exploité ce trou. Deux « high » de code montrent en prime que les outils qui *définissent* l'espace exit-code peuvent eux-mêmes le violer sur une entrée malformée.

**Ce qui mènerait à 17-18/20** : action #1 (harnais versionné) + action #2 (exit-code sur 7/7) + #3 (bug `$type`). L'essentiel est faisable « en une après-midi » selon l'audit tests — l'infrastructure de fixtures existe déjà, il ne manque que l'assertion exécutable.
