# Normalizing author HTML into a wireframe

Normalization never edits its source. It classifies an input as `canonical-wireframe`, `repairable-wireframe`, `html-document`, `html-fragment`, or `ambiguous`, inventories author content, and rebuilds into a fresh generated shell through the governed applicator.

## Preservation order

1. Brief-linked content and controls.
2. Meaningful order and grouping.
3. Decision-relevant states and interactions.
4. Brand/context evidence covered by active pillars.

Document wrappers, presentation chrome, excessive annotations, unproven brand styles and interactions that hide essential states do not migrate by default. Scripts, loaders, analytics and external dependencies never cross automatically.

## Decisions that stop before writing

- Several unit/state mappings remain defensible.
- A script creates visible content or a required interaction without a declarative mapping.
- A dependency is unreadable and materially changes the view.
- A transformation changes meaning, user-flow order or business content.
- Equal-authority references contradict one another.

Otherwise the agent reviews the inventory itself and writes. Human confirmation is requested only for one of these semantic forks, not for routine shell reconstruction.

## Completion proof

The source checksum is unchanged; every inventoried block has `preserved`, `transformed`, `omitted`, or `unresolved`; unresolved is empty; the output is statically and visually green; and the response lists each disposition. The inventory stays outside the visible board.
