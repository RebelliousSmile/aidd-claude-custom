Behavioural tests for the **`*-optimize` family** — `overcode:web-optimize`, `overcode:data-optimize`, `overcode:ap-optimize`, `overcode:seo-optimize` (`plugins/overcode/skills/<x>-optimize/SKILL.md`) — verifies that a run **names the provenance of the checklist it loaded** and **reports the state of the plugin pivot for each detected stack**.

**This is the regression spec for issue #11.** It is expected to FAIL on most rows at run 1: at the time run 1 was recorded, the promise was written in `plugins/overcode/README.md:7` and `plugins/overcode/docs/concepts.md:25` — both closing on *« l'absence est énoncée »* — and implemented nowhere. Those two lines were rewritten in part 2 of the plan to state the four states explicitly; the promise moved, the implementation did not. The decisive absence is DEC-010 §1's second state — *a provider exists, nothing is installed here* — which no current output can express.

This suite is **distinct** from:
- `pivot-install-scenarios.md` (`plugins/sc-tiers/skills/setup/evals/`) — what the **installers** claim to have written.
- **this file** — what the **consumers** say about what they loaded and what was missing.

## How to run

Agent-as-`<x>-optimize` (dry-run, **READ-ONLY** on the fixture): load the target `SKILL.md`, its Step 2 rung, the reference files named in the row, and this suite; then reason out what the skill **would emit** for that fixture, and judge that text against the pass criteria. Nothing is written anywhere.

**Decisive observables:**
- The judgement bears on **emitted text**, never on a return value or an internal state.
- Both fields must be present and independent: a run can legitimately be `pivot : not installed` **and** `source : repli interne <file>` — the two axes do not exclude each other, and collapsing them into one alternant loses the receipt.
- Every plugin name and every install command must be traceable to `pivot-providers.md`, **in the form that table carries** — `/sc-js:sniff`, not a prose restatement of it. A guessed name is an automatic FAIL, even when correct.
- Fixture untouched: list `.claude/rules/07-quality/` before and after. `git status` alone does not conclude — it is mute on `email-to-markdown/site` (gitignored receptacle) and inoperative on `email-to-markdown/app` (*dubious ownership*).
- **Do not read the appendix or the Results log before grading.** Both record what was measured against a text that has since changed.
- **Tally the two families apart.** A red on S3 or S11 says nothing about the receipt; a green on the receipt rows says nothing about detection.
