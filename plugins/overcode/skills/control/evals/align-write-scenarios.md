Behavioural tests for **overcode:control** (`plugins/overcode/skills/control/SKILL.md`, action `06-align`) — verifies the single write path of the whole skill. The decisive properties: `06-align` writes **`testing-domains.md` under its own pen** and the project's strategy **only by delegation to its owner** — `aidd-context`'s project-memory skill, designated **by role and never by a frozen action number**; everyone reads, only `06-align` writes, and only after validation; a document left in template form is treated as **absent** for the tier decision with forced matching applied — and the run must **say which of the three forms** it met; *undocumented* is reported as undocumented, **never** as "implicitly follows the default", and never as an absence of limit either, since the matrix ceiling holds without any document saying so; there are **five gap natures**, with the two mixed ones splitting **measurement → facts block, response → strategy block**, the validated response landing where the domain judgement lives; the two blocks are approved **independently**; a missing document is never created by default; the write route is **announced**; the written file is **re-read and compared**, divergence reported and never fixed in place; **adding is the default**; outside a phase switch the action only describes; the phase is written **as a declaration, never as a measured fact**; « aucun domaine » is a valid answer that moves the project into the **hors-domaine column**, not into a fallback; and the two number constraints are proposed as **two objects, never merged** — the project cap as the project's own measured density, the `phase × domain-level` cell's ceiling as the fixed number the matrix states.

> **Rewrite of 2026-07-29 — S20, one half withdrawn (not deleted, per DEC-006).**
> S20 formerly required the proposed cap to be **a plain absolute number, with the median stated beside it as an observation**. User arbitration of 2026-07-29 **retains the density as the project cap**, so that half is withdrawn.
> The motive: the row applied to the **project cap** a rule that bears on the **cell ceiling**. `docs/control.md` › *Le plafond* (l.79) rules out expressing **the matrix ceiling** as a multiple of a median — a ceiling has to hold for a cell with no test in it yet, and multiplying an empty distribution produces no number. That objection does not reach a project cap, which is by construction an observation made on a populated distribution; `docs/control.md` › *Densité et plafond ne se remplacent pas* (l.306-310) is the page rule that keeps the two apart, and S20 had collapsed them. The rewritten half scores the **separation** of the two objects instead of the form of one.
> The second half — the degenerate case of a cap asked for while the coverage report carries no branch data — **is unchanged and stays**, and is the half `app` actually exercises.
> Page-side residue, **reconciled 2026-07-29**: the entry under *Ce que `06-align` écrit* read *Un plafond se propose en nombre, jamais en multiple de médiane* and carried the withdrawn half at the page level — flagged in run 5's frictions and left standing through part 3's first pass. It now states **three** objects separately — the cell ceiling (the matrix's fixed number, in force whatever is proposed, never a median multiple) · what the action actually **proposes** (the measured density, which observes and is never named a cap) · the **declared** project cap (the project's own decision, a number and never a median multiple) — with the motive of the change written into the entry. That is also what `06-align.md` says, in that order; run 6's friction 9 read the two as disagreeing on vocabulary, and the disagreement was the page's missing third object. The *Pointe vers* cell of S20 no longer needs to except the entry.

This suite is **distinct** from:
- `phase-scenarios.md` — where a phase value comes from and how it is reported.
- `confirmations-scenarios.md` — the four components of a phase-switch batch.
- `domains-scenarios.md` — how a domain term resolves against the code, and what the catalogue is a floor for.
- `matrix-scenarios.md` — what a cell requires and how high its ceiling sits. Here the ceiling appears only as something proposed to a project, in a form.
- **this file** — what gets written, into which file and which block, and under what discipline.

## How to run

Agent-as-`overcode:control` (dry-run, READ-ONLY on the fixture): for each scenario, load **only** the files in its *Judge load path*, plus this suite. Reason out the response and — the observable this suite lives on — **the exact intended write: path, block, literal content, route taken**. Nothing is written to either fixture.

**Every scenario is scored on the intended write, not on the prose around it.** `06-align` is the only action in the skill that touches disk; a suite that judges its explanations rather than its writes tests the wrong thing.

**S7 and S8 are the fixture contrast and are judged as a pair.** Both documents are filled; one is false, the other silent. A run that gives them the same nature has collapsed the distinction the five-nature table exists to hold.

**Record the intended write path per file, not per action.** Since part 2 the action has two standings — direct writer of `testing-domains.md`, delegating writer of the project's strategy — and S10, S18 and S22 all turn on which standing was used for which content. A run log listing "writes: yes" is unscoreable here; list the paths.

**Seven rows were expected to come out wrong: S4, S10, S11, S19, S20, S22 and S23 — and all seven are green since run 5.** The announcement is kept, rewritten rather than struck, because it is the reproduce-then-confirm record of parts 1-3: three of them (S11, S19, S23) were red against `actions/06-align.md:81`, which routed what no domain covers to a generic `critical journeys` fallback, and S20 was red against `:87`, which asked for a density where the page asks for a number. **Neither line exists any more** - both were replaced by the refonte, which is exactly why the rows flipped. S4, S10 and S22 were red against a different absence: the second standing this suite scores — direct writer of `testing-domains.md` — is stated nowhere in the skill. `testing-domains.md` appears in no `SKILL.md`, no `actions/*.md` and no `references/*.md`; `06-align.md:81` still says the domain list *« belongs here and nowhere else »*, "here" being the one document step 8 delegates. Any row whose criteria require the domain list to leave by its own path therefore fails until part 3 gives the action that path. Score each FAIL against the line named in its row, and do not soften it into a friction because the reasoning around it was sound: the instruction is what the next reader will follow. Three rows failing on one line is not redundancy — they meet it from the undeclared zone, from the recorded answer, and from a pre-model document, and part 3 has to fix all three entries.

**No row here is scored on the presence of a word.** Every criterion above names a behaviour of the intended write — a path, a block, a nature, a route, a stated form. A run that awards a PASS because the response contained *hors-domaine* or *plafond* has scored the vocabulary; the suite is written so that the vocabulary alone never satisfies a row.

**The `Page rule pinned` column is for the maintainer, not for the judge.** It records which rule of `docs/control.md` a row protects, so that a page edit can find the scenarios that guard it. The judge never loads the page — its reading is bounded by the *Judge load path* column.

**Decisive observables** (write-scoped):

- **One writing action.** Any intended write from an action other than `06-align` is an automatic FAIL.
- **Two write paths, two standings.** `testing-domains.md` direct, the strategy document delegated. Either one crossed over is a FAIL.
- **Nature → block, per gap.** Recorded explicitly; the two mixed natures must appear in both.
- **No creation by default.** A missing document produces an offer, never a file.
- **Re-read and compare.** Absence of the step is a FAIL even when the write would have been faithful.
- **Phase written as declaration.** Any measured-fact framing is an automatic FAIL.
- **A proposed ceiling is a number.** Any figure expressed as a multiple of anything is an automatic FAIL.
- **No generic fallback anywhere in the output.** No critical-journey list, no default inventory.
