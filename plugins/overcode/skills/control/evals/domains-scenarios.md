Behavioural tests for **overcode:control** (`plugins/overcode/skills/control/SKILL.md`, actions `02-audit` / `04-strengthen` / `05-stats` / `06-align`, references `references/domain-catalogue.md` / `references/pivot-contract.md`) — verifies the domain mechanism end to end. The decisive properties: the **project** declares *which* domains exist and at *which level*, the **pivot** declares *how* to spot them in this stack, and the pivot **completes** an incomplete declaration and never overwrites one the project wrote about its own code; the file `aidd_docs/memory/testing-domains.md` is the domain authority, written by **`06-align` alone**, and `testing.md` is **never written by this skill**; terms resolve as **literal, case-insensitive** strings plus paths, **no regex**; a name **with no level designates no column**; a domain passed as an argument **is its own confirmation** and only its level remains open — catalogue hit → no question, catalogue miss → **ask, never guess** — and the answer is **valid for the invocation only**; the catalogue is a **detection floor, never an inventory**; **multiple membership** is admitted; a domain **designates a column and restricts nothing**; unmatched code **stays in the analysis and is reported with the term that failed to recognise it**, bounded; drift is **reported, never applied**; and there is **no generic fallback** — hors-domaine is a column of the matrix, not a repli.

**Rules that die here with no scenario carrier** — recorded so their disappearance is a decision and not an omission:
- **The `critical journeys` fallback.** Old S1 required it to be applied and labelled approximate; the page now abolishes every generic substitute for an absent domain, and the case is a *column*. What used to be the fallback's scenario is now S1's inverse: producing that list is the FAIL. The inherited friction "*the fallback is never declared approximate on its own terms*" is therefore closed by removal, not by repair.
- **A domain list proposed by the skill by default.** Old S2 pinned that the skill proposes none. The catalogue now exists and is consulted — but as a **detection floor**, which is a different object from a default list, and S2 is rewritten around that distinction rather than deleted.

This suite is **distinct** from:
- `matrix-scenarios.md` — what the designated column then requires, and its ceiling.
- `authority-scenarios.md` — that a domain decides no required proof.
- `phase-scenarios.md` — the phase, which *may* narrow the universe provided it lists exclusions; a domain may not, at all.
- `align-write-scenarios.md` — writing the domain file, and the write-ban on `testing.md`.
- **this file** — declaration, resolution, level, and the non-restriction guard-rail.

## How to run

Agent-as-`overcode:control` (dry-run, READ-ONLY on the fixture): load **only** the files in each scenario's *Judge load path*, plus this suite. Reason out the response and the exact set of intended writes, then judge against the pass criteria.

**S4 and S5 are the load-bearing pair and must be judged together.** S4 asks whether the non-matching file is still *there*; S5 asks whether the *reason* it ranked low is visible. A run can pass S4 and fail S5 — the file is present but indistinguishable from a clean one — and that is the failure mode the guard-rail exists to prevent. Score them as a pair before scoring the suite.

**S10, S11 and S12 are the argument path and are scored as a chain.** S12 says which branch resolved the column, S10 says what the branch cost in questions, S11 says what it wrote. A run that resolves correctly and persists the answer has passed two and lost the one that matters.

**The reading under test throughout this suite is substring, case-insensitive, over identifiers and paths.** `auth` matches `suddenly/fediverse_auth/views.py` because `auth` is a substring of `fediverse_auth`; `federation` does not match the same path — no shared substring exists between the two strings. S13 pins this literally over a single term; S14 relies on it holding for two different terms over the same path at once. The page states "littéral, insensible à la casse, plus les chemins, pas de regex" but does not spell out *substring* — a case-insensitive full-token-equality reading is equally literal and equally non-regex, yet it resolves a different set (`auth` would then match nothing in `fediverse_auth`, since the token is `fediverse_auth`, not `auth`). The page ought to state the substring clause explicitly; this suite tests the substring reading regardless.

**The residue is one trace, over both sides.** `05-stats` counts source files, `02-audit` holds the test-side half, and `06-align` consumes them as a single drift signal — so a run reporting a residue must say **which side it counted**. Two traces that are never stated to be the same trace, feeding one consumer, is a friction recorded against the target, not against the fixture. *(Inherited friction, carried forward with this instruction to score it explicitly rather than pass over it.)*

**A `domain` argument is in force in every action that takes one.** `05-stats` is not the only place the provenance rule may live: S4 and S6 run on `04-strengthen` and `02-audit`, and if either describes `domain` as "declared by the project" without admitting the argument, those scenarios pass on a rule stated in a third file. Record where the rule was read from. *(Inherited friction, now scorable.)*

**S2 is an assumed yellow.** It judges the skill's self-description of where a domain list comes from, not an act performed on the fixture — the judge is trusted to read a stated distinction (catalogue-as-floor vs. project-inventory) rather than observe a behaviour. Kept despite this because it is the **sole carrier** of "the catalogue is a detection floor, never an inventory": no other scenario in this suite would catch a skill that silently reads the catalogue as this project's domain list.

**The `Page rule pinned` column is for the maintainer, not for the judge** — it records which rule of `docs/control.md` a row protects. The judge never loads the page.

**Decisive observables** (write-scoped):

- **The classifiable universe is domain-invariant.** Diff the file set with and without the `domain` argument: it must be identical. Only the order changes.
- **The exclusion list has exactly three legitimate sources.** A fourth entry sourced from a domain miss is an automatic FAIL.
- **No invented domain, and no catalogue entry presented as this project's.** Either is an automatic FAIL.
- **No `critical journeys` list, anywhere.** Its presence is an automatic FAIL.
- **Every domain carries a level, or it designates nothing.**
- **Intended writes to `testing-domains.md` = ∅** for every action but `06-align`; intended writes to `testing.md` = ∅ for **all six**.
- **`scope` + `domain` → halt.** Any output produced past that point is a FAIL.
