# Control — Density, Coverage Reading & Measurement Bounds Behavioural Test Scenarios

Behavioural tests for **overcode:control** (`plugins/overcode/skills/control/SKILL.md`, actions `04-strengthen` / `05-stats`, references `references/test-density.md` / `references/pivot-contract.md`) — verifies the measurement layer. The decisive properties: density is read **against the project's own median**, alerting past 3×, never against an imported absolute; an outlier **points and never qualifies**, and admits two readings to be discriminated before either is emitted; density is **not a target**; density and ceiling are **not two rival measures** — one observes a population and requires nothing, the other is an exigence uttered by the phase before any datum is read, so neither ever stands in for the other; `limit` comes only from an explicit test-count limit; a coverage percentage is never a budget; **no percentage is produced at all** — orders, never shares; the reading is `covered`/`total`, an absence at the glob means **not covered**; the source glob drives the universe; the **four** degenerate cases are reported in order, outermost fact first; the snapshot displays what is declared and what is measured and **deduces nothing from the two** — a `DOMAINES exigé / trouvé` block of exactly two columns, no flag comparing proof forms against each other, and the `excluded` table kept; a declared gate is reported as **invoked or inert**, never merely "configured"; and an external boundary is worth **one** test by default.

This suite is **distinct** from:
- `authority-scenarios.md` — that density never changes a tier.
- `phase-scenarios.md` — that the number the phase now carries is a ceiling and not a coverage target, and that an absence means the same thing in every phase.
- `matrix-scenarios.md` — what a cell requires and how high its ceiling sits. Here the ceiling appears only as the thing density must not be confused with, and as the figure the snapshot displays without applying.
- `domains-scenarios.md` — that a domain does not shrink the universe.
- **this file** — the arithmetic itself, and how its results are stated.

## How to run

Agent-as-`overcode:control` (dry-run, READ-ONLY on the fixture): for each scenario, load **only** the files in its *Judge load path*, plus this suite. Reason out the response and the exact figures the run would emit, then judge against the pass criteria.

**S2 is checked mechanically, not by reading.** Scan the produced report for the `%` character and for the words "percent"/"pourcentage". **Three hits are sanctioned, and only three** — they are exemptions by *provenance*, not by location, and each must be named as such by the run:
> 1. the `declared` line of the STRATEGY block, quoting the project's own figure verbatim;
> 2. a figure quoted from a tool's own report **as that tool's output**, attributed to it (`SKILL.md` › *Transversal rules*) — pytest-cov's `TOTAL … %` reproduced under its own name, never re-derived and never re-aggregated;
> 3. the skill's own documented **`0/0 → 100 %` trap note**, which is instruction prose about how a ratio misreads, reproduced in output rather than computed on the project.
>
> Any other hit is a FAIL. **A sanctioned hit that does not say which of the three it is scores as unsanctioned** — an unattributed percentage is indistinguishable from a computed one, which is the whole point of the rule. Keeping the check mechanical matters: it is the criterion most likely to be waved through by a judge reading for intent. Narrowing it to computed figures is a deliberate arbitration of 2026-07-28, recorded in the log below — the earlier absolute form contradicted both the authority page (which forbids *producing* a percentage, not repeating one) and S3 of this same suite.

**The degenerate cases are judged on order and on number.** S11, S12–S14 and S15 all admit outputs containing the right facts in the wrong sequence, or the right fact under the wrong case number. Record which fact the run leads with, and which number it puts on it. The numbering moved in part 2 — there are four cases, and *insufficient population* slid from 3 to 4 — so a run reusing the old numbers is reading a stale copy of the model, which is worth knowing on its own. **Case 4 has no scenario in this suite**: it is unreachable on both fixtures (see the header), and a suite that forced a case-4 row into existence on `ai-hub` would be scoring a correct run against a state the fixture cannot produce — that was the defect in the previous S12, now repaired by narrowing S12–S14 to case 3 only.

**S19 and S22 are scored on an absence.** Both ask what the snapshot no longer prints. Search the produced report for the removed artefact — a per-tier count or ratio for S19, any flag phrased as a comparison between `contract` and `e2e` for S22 — and score the hit, not the intent. A run that keeps the artefact while narrating that it is deprecated is a FAIL: the report is the output, the narration is not. For S22 specifically, score the hit even when the fixture could never have tripped the ratio in the first place (`app` has no `e2e` directory): the FAIL is evaluating the ratio at all, not the ratio's result, so the row is not made vacuous by the trigger condition never firing.

**S21 is the boundary between displaying and deducing, and it is easy to score wrongly in both directions.** Two columns side by side is a display. Any figure that consumes both is a deduction. Judge the *number of columns and derived values*, not the wording around them.

**The `Page rule pinned` column is for the maintainer, not for the judge.** It records which rule of `docs/control.md` a row protects, so that a page edit can find the scenarios that guard it. The judge never loads the page — its reading is bounded by the *Judge load path* column.

**Decisive observables** (write-scoped):

- **Zero *produced* percentages in the output.** Mechanical check, automatic FAIL — a percentage that only *reproduces* the project's own declared figure (`declared` line) or the skill's own `0/0 → 100 %` explanatory note is exempt; see S2.
- **The universe is glob-derived.** Never the coverage report's file list.
- **No density where there is no denominator.** No approximation, no line-count substitute.
- **The unmatched-file count is present in every run**, degenerate or not.
- **No work justified by a number going up.** Neither coverage nor density.
- **No per-tier count, no per-tier ratio, no flag comparing tiers.** Mechanical check over the whole report.
- **The `DOMAINES` block has exactly two columns**, and no value derived from them.
- **The `excluded` table is present** whenever the phase excluded anything, one motive per file.

**Rewrite log — S2's check procedure and S25's reachability, 2026-07-29 (DEC-006).** Both were rewritten, not deleted.

**S2** carried two forms of the same criterion in the same file: the pass-criteria cell sanctioned two classes of percentage, *How to run* still sanctioned one location.
