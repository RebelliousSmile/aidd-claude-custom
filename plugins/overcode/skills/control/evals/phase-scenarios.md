# Control — Phase Resolution, Provenance & Switch Behavioural Test Scenarios

Behavioural tests for **overcode:control** (`plugins/overcode/skills/control/SKILL.md`, actions `03-configure` / `04-strengthen` / `05-stats` / `06-align`, reference `references/phase-framework.md`) — verifies how the phase enters the model and what it is allowed to bound. The decisive properties: the phase is **never inferred**; the question is asked **before** anything is classified or proposed; value and provenance are reported as **two lines that never merge**; `unanswered` ⇔ `undetermined` is the **only** forced pairing; `default` does not re-ask, `undetermined` does; `undetermined` **switches as soon as a phase is declared**; a phase argument governs the current run only and is never written; a divergence between argument and declaration is reported; the phase now **does** carry a number — the ceiling of a cell — and that number is **never a coverage threshold and never a floor**; a phase that narrows the analysed universe **lists what it excluded**; and no phase changes what a coverage datum *means*.

This suite is **distinct** from:
- `matrix-scenarios.md` — what each cell requires, and what its ceiling refuses.
- `authority-scenarios.md` — what the phase's decision forbids every measuring instrument from doing.
- `align-write-scenarios.md` — how `06-align` turns a spoken answer into a written declaration.
- `confirmations-scenarios.md` — the phase-switch batch and its four required components.
- **this file** — where the phase value comes from, how it is reported, and what it may bound.

## How to run

Agent-as-`overcode:control` (dry-run, READ-ONLY on the fixture): for each scenario, load **only** the files in its *Judge load path*, plus this suite. Reason out the response and the exact set of intended writes, then judge against the pass criteria.

**Two-run scenarios (S12, S15) are judged on the Δ, not on either run alone.** Score the pair: what must differ, and what must not. A suite that judges S12's two runs independently will pass both while missing the defect it exists to catch. **S5 and S16 are no longer such a pair.** S5 was split so its executable half — a spoken `default` — stands alone, judged on its own single run; S16 carries the other half — `default` declared in `testing.md` — as its own N/A row, not a Δ partner.

**S10 and S17 are the inversion, split from one scenario into two, and are scored together.** S10 fails a skill that still declares the phase incapable of a number; S17 fails a skill that has acquired a number of the wrong species. Record which one moved.

**S16, S17 and S18 are appended, not inserted next to their origin.** They are the split-offs and the addition produced by this suite's repair pass (S16 from S5, S17 from S10, S18 new), kept at the end so S1–S15 retain the numbering their prior Results log runs were scored against. Reading order is therefore not always adjacency of related scenarios — each row's Situation says where it came from.

**Friction, settled.** "A correct act reached for the wrong motive is a **friction**: the verdict cell reads `FAIL` and the note says so. Friction is never a PASS." This settles a real ambiguity: the word used to mean "not a FAIL" in S13 (dropped now — silently ignoring a parameter is a plain FAIL) and "not a PASS" in S7 (the correct reading, kept as this suite's definition). **S7 is an assumed yellow**: it judges a motive (consent vs. mechanics), not only an act, and the page makes that motive normative — the judge is trusted to read the stated reason, not merely the outcome.

**The `Page rule pinned` column is for the maintainer, not for the judge** — it records which rule of `docs/control.md` a row protects. The judge never loads the page: knowing a rule the skill does not carry produces a PASS the skill has not earned.

**Decisive observables** (write-scoped):

- **No phase value the user did not supply.** Any inferred phase is an automatic FAIL.
- **Two lines, always.** Value and provenance never appear fused.
- **Intended writes to the project document = ∅** for every action except `06-align`, and for `06-align` only after validation.
- **A narrowed universe always ships its exclusion list.** A count without the list, or a list without the motive, is a FAIL.
- **The phase's number is a ceiling on proofs.** Any reading of it as a target, a floor or a coverage figure is an automatic FAIL — the ceiling is a count of established proofs supplied as a premise of the cell, never derived from a file count.
